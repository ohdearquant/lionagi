    Files and processes¶

    Filesystem and process helpers preserve each caller's path admission, publication, locking and cleanup boundary. Similar-looking calls remain separate when inode behavior, platform locking, process ownership or error results differ.

    Operation boundaries¶

    Operation Behavior
    Root and path admission Workspace-root resolution preserves empty/None/cwd, expanduser and resolve behavior. Other path consumers retain their own dot/backslash, absolute/traversal, symlink and containment checks, error envelopes and mkdir order.
    Atomic writer ownership Private atomic writers retain their owning modules, None return, non-finite check order, mkstemp with mode 0o600, serializer bytes, replace, BaseException cleanup and any post-publication chmod.
    File-lock platform semantics MCP Windows byte locks seek byte zero without restoring the offset; plugin locks restore it after success. POSIX shared/exclusive flock and missing/required/optional lock policies remain distinct.
    Process identity and liveness lionagi.cli._kill_service.check_pid_identity delegates to the inclusive 0.1s comparator while preserving expected-time admission, one probe, unknown/gone/found verdicts and later command/session checks. MCP low-PID waitpid and OSError behavior differs from CLI; admin retains zombie checks and its 1.0s tolerance.
    Capped stream readers Capped readers retain their head-versus-tail selection, EOF draining, byte return shape, truncation flags, logging and per-stream limits.
    Child exchange ownership The child exchange owns env/cwd/trusted executable, state-URL stripping, witnessed process-group cleanup, outcome callbacks and best-effort two-second reap.
    Temporary signal handlers Monitor uses temporary_signal_handlers, preserving main-thread/None-handler abstention and restoration of installed handlers.
    In-place publication In-place JSON/Markdown/YAML writes preserve inode, hard-link, symlink, reader, mode and newline behavior. Existing fixed-temp or unique-temp publishers retain their own cleanup and non-finite ordering.
    Non-finite write policy Writers that permit stdlib NaN/Infinity keep that admission, flush/fsync/replace and their existing Exception suppression behavior.
    Lock lifetime and availability Native lock wrappers retain Windows unavailable/unlocked behavior, POSIX error policy, shared reads, exclusive writes, fd lifetime and explicit unlock.
    Trusted child cleanup Hook/dispatch exchange retains pre-spawn serialization, timeout classes and witnessed cleanup. Other runners keep copy-then-hash executable trust, capped streams, auth lookup duration and their existing post-SIGKILL wait.
    Shell and subprocess results Shell choice, control/split grammar, sessions, env, capped byte drains, locale text and exact timeout/spawn/error results remain caller-specific. A shell-pattern change can reject input in tools while enabling shell execution in engines.
    Signal-sensitive entry points Signal-sensitive entry points retain asyncio.run, main-thread handlers, SIGTERM behavior, lock lifetime and Exception-only outer catches.
    Workspace root helper Tool constructors share the private _resolve_workspace_root with unchanged defaults, empty/None/current-cwd and expansion behavior.
    Path helper ownership Path helpers retain their current owning modules and public aliases, including source initialization and error behavior.
    Writer API boundaries Writer interfaces retain their current return type, serializer, mode, cleanup and publication ordering.
    Lock facade boundaries Lock facades retain platform availability and file-offset restoration rather than adding a new cross-platform policy.
    Process exports and start-time comparison Existing process exports retain separate liveness, reaping and unknown-identity contracts; comparator reuse adds no public process names.
    Reader retention policy Head/tail stream readers keep their existing allocation and zero/negative cap policy rather than adopting a normalized result type.
    Specialized runner options The narrow shared exchange omits specialized cwd/env/executable/cap controls; those runners keep their own process lifecycle and result policy.
    Synchronous process boundary Synchronous subprocess boundaries retain native output decoding, exceptions, sessions and terminal signal behavior.
    Shell-control patterns Caller-owned shell-control patterns preserve the different authorization effects of ${...} recognition.
    Signal handler ownership Temporary signal-handler ownership stays with the monitor scope and restores the handlers it actually installed.

    Shared helpers¶

    Tool constructors share _resolve_workspace_root. Monitor signal scopes use temporary_signal_handlers. lionagi.cli._kill_service.check_pid_identity delegates its inclusive 0.1s comparison to start_time_matches, while retaining PID admission, one process probe and command/session checks. Admin liveness keeps its distinct 1.0s policy.
