### Fixed

- A resumed `li o flow` run started with `--mcp-config` now starts with the MCP servers its
  first run read from that file, not what the file holds at resume time. The run copies the set
  into its run directory (`mcp-config.json`, readable by its owner alone), its checkpoint points
  at the copy and keeps the named path as `mcp_config_named`, and each resume copies it again into
  its own run directory. A resume whose copy is gone is refused, naming the file. Checkpoints
  written before this change read the named file again.
