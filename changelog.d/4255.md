### Changed

- `li agent` on an `anthropic/<model>` profile now moves to `claude_code/<model>` when the account router refuses the run's first request with `budget_exhausted` or `account_blocked`, before anything was sent.
  The run prints one warning naming the refusal code and the new model, records the original model, the model used and the refusal code in `subscription_fallback` in `run.json`, and records `claude_code` and its model as the run's provider and model.
  A run on the read set (`api_tools: read`) continues with only Claude Code's `Read`, `Grep` and `Glob` tools, and a run on the write set with `Read`, `Grep`, `Glob`, `Edit`, `Write` and `Bash`, so the switch gives a run no tool its API set did not have; a profile that names its own `tools` keeps them.
  The write set continues without the macOS sandbox its editor and bash ran under, because Claude Code has no filesystem sandbox, and the warning says so.
  No MCP server is handed to the run on the subscription route, as none was on the API route, and the CLI loads no MCP config of its own.
  `subscription_fallback` also records `tools`, the `--tools` value the run continued with (null when it has every built-in tool), and `sandbox_dropped`, true when the run's API tool set was sandboxed and the subscription route ran it without that sandbox.
  A refusal after a reply, any other router code and any other provider still fail with the routing error, and a run moves at most once.
