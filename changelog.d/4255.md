### Changed

- `li agent` on an `anthropic/<model>` profile now moves to `claude_code/<model>` when the account router refuses the run's first request before anything was sent, with `budget_exhausted`, or with `account_blocked` when every blocked account hit its spend ceiling (`ceiling_exceeded`).
  The run prints one warning naming the refusal code and the new model, records the original model, the model used and the refusal code in `subscription_fallback` in `run.json`, and records `claude_code` and its model as the run's provider and model.
  A run on the read set (`api_tools: read`) continues with only Claude Code's `Read`, `Grep` and `Glob` tools, and a run on the write set with `Read`, `Grep`, `Glob`, `Edit`, `Write` and `Bash`, so the switch gives a run no tool its API set did not have; a run whose API tool set has no such list does not switch and fails with the routing error.
  A read-set run switches without a permission bypass, because Claude Code's `Read`, `Grep` and `Glob` need no approval, even when the run was started with `yolo` or `bypass`; a write-set run keeps its own `yolo` and `bypass` on the switch, because Claude Code in print mode cannot approve `Edit`, `Write` or `Bash` without them.
  The warning says that Claude Code's tools are not confined to the working directory the way the API route's tools were, and, when the switched request carries a permission bypass, that Claude Code runs its tools without asking.
  The write set continues without the macOS sandbox its editor and bash ran under, which confined file writes and, unless the profile set `api_network`, network access, because Claude Code has no filesystem sandbox, and without the API route's checks that refuse destructive commands (bash) and email addresses in outbound headers (bash and editor); the warning says so.
  No MCP server is handed to the run on the subscription route, as none was on the API route, and the CLI loads no MCP config of its own.
  `subscription_fallback` also records `tools`, the `--tools` value the run continued with (null when it has every built-in tool), `permission_mode`, the permission mode on the switched request (`bypassPermissions`, or null when it carries none), and `sandbox_dropped`, true when the run's API tool set was sandboxed and the subscription route ran it without that sandbox.
  The Claude Code process of a switched run gets this process's environment without the credential names the API route's commands also went without (the names the run's configuration declares, the shared sensitive-name patterns and the shell startup names), for the read set as for the write set, so that no API key reaches Claude Code or its Bash tool and an `ANTHROPIC_API_KEY` is not billed in place of the subscription; Claude Code's own `CLAUDE_CODE_OAUTH_TOKEN` is kept.
  `subscription_fallback` also records `env_removed`, the sorted names (never the values) of the variables this process held that the switched process's environment does not carry.
  A refusal after a reply, any other router code and any other provider still fail with the routing error, and a run moves at most once.
  A run pinned to an account with `LIONAGI_API_ACCOUNT`, a run refused with `account_blocked` for any other block reason, a run whose block reasons cannot be read, and a run whose Claude Code request does not take the child environment do not move: each prints one warning saying why and fails with the routing error.
