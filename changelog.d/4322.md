### Fixed

- The pre-turn khive recall, feedback, compose and writeback client registered for a profile's `khive_injection` opt-in now acts as `agent:<profile>` (or `agent:anonymous`), the same actor the khive servers forwarded to that agent use, instead of as whoever launched the process. This covers `li agent -a <profile>` with or without a role, and `li o flow` orchestrators and workers, whether their branch is built from an authored body or by the agent factory. `create_agent` takes a new `khive_actor` argument for this, and `KhiveInjectionProvider` takes an optional `actor`; either sets `KHIVE_ACTOR` in the environment of the khive MCP server the provider spawns, replacing any value configured there. The variable is a fallback, as for the servers forwarded to the agent: the server starts in the launching process's working directory, so an actor config there still takes precedence. Without an actor the server is left as configured, which is still the case for agents built by the orchestration engines and by `create_agent` callers that pass none.
