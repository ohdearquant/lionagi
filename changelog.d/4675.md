### Fixed

- Each session chunk of the retention prune no longer reads every terminal session in the store. The
  six statements that clear or delete a chunk's session references re-check that each referenced
  session is still terminal by looking it up by id, so a chunk's time inside the state store's write
  lock follows the chunk's size rather than the store's. A partial index, `idx_dispatch_outbox_session`,
  lets the `dispatch_outbox` statement find its rows without scanning the table; existing stores gain
  it when the schema-managing process opens them, and that first open builds it once, holding the
  write lock while it does.
