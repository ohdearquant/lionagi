# JSON serialization contracts

The shared JSON helpers serve compatible decoding and compact identifier bindings. Native codecs remain where admission, options, exact bytes, error metadata, stream ownership or fallback selection are observable.

## Operation boundaries

| Operation | Behavior |
| --- | --- |
| Shared compatible decoding | Compatible model decoders use `ln.json_loads` and retain the native JSONDecodeError alias and surrounding caller behavior. |
| Native decoder admission | Native decoders retain bytes/bytearray/string admission, arbitrary-size integers, non-finite values, surrogates, hooks and native error metadata where exposed. |
| Schema and extraction fallback | JSON/YAML/spec fallback and structured extraction retain the representation selected by each failure and the original error/cause boundary. |
| File-stream encoding | File writers retain encoding, indentation, sorting, custom defaults, stream ownership and write/error ordering. |
| Inline and output encoding | Inline/output encoders retain exact emitted text and their surrounding serializer or file-publication ownership. |
| SQL and transport bindings | SQL/document/transport serialization retains its codec policy; compatible schedule identifier-array bindings use the shared serializer. |
| CLI and log text | CLI/log text retains its formatting, newline/framing and failure behavior. |
| Custom defaults | Custom-default and unsupported-type handling retain their original admission and fallback policy, including full default=str text. |
| Canonical hash input | Canonical digest inputs retain exact bytes and ordering because changing serialization changes durable identifiers. |

## Shared helpers

Compatible model decoders use `ln.json_loads`; the schedule identifier-list bindings use `ln.json_dumps`. Callers that expose the stdlib keyword/error surface, exact serialized bytes or stream ownership use their native codec.
