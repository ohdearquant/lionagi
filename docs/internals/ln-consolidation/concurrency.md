# Concurrency contracts

Shared concurrency helpers cover compatible worker, delay, clock and scope operations. Native primitives remain where callers own concrete task handles, synchronous locks, queue APIs, loop affinity or a different cancellation policy.

## Operation boundaries

| Operation | Behavior |
| --- | --- |
| Shielded worker offloads | Compatible worker calls use `run_sync`, preserving arguments, copied context, default shielding, results and caller-specific errors. |
| AnyIO delays | AnyIO delay callers use `sleep` with the same delay and cancellation behavior. |
| Scheduler delays | Scheduler delays use `sleep` while retaining stopping checks, stray-cancellation handling and monotonic deadline arithmetic. |
| AnyIO elapsed clock | AnyIO elapsed reads use `current_time` in the active backend clock domain. |
| Loop elapsed clock | Async loop-clock consumers use `current_time`; synchronous paired monotonic measurements remain native. |
| Cancellation scopes | Compatible cancellation scopes use the shared `CancelScope` with the same lexical ownership. |
| Timeout scopes | Compatible timeout scopes retain their existing `fail_after` or `move_on_after` error and suppression policy. |
| Returned awaitable dispatch | The scheduler awaits returned awaitables through `maybe_await`, preserving synchronous results and its existing outcome boundary. |
| Abandonable worker offloads | Terminal callbacks and notifications pass `abandon_on_cancel=True` explicitly; envelopes, deadlines, cancellation and outcome handling remain caller-owned. |
| Native locks | Native asyncio locks retain uncontended scheduling, concrete type, reacquisition behavior and `locked()` consumers. |
| Native events | Native events retain already-set wait scheduling, reset/clear behavior and concrete readiness identity. |
| Native semaphore | The native semaphore retains its `locked()` precheck and uncontended acquire window. |
| Native queues | Native asyncio queues retain unbounded/maxsize0 semantics, immediate reads, QueueFull/QueueEmpty and qsize/empty APIs. |
| Native gather | Native gather retains task/future handles, ordered return_exceptions results, sibling-lifetime and BaseException behavior where these differ from structured gather. |
| Default-executor threads | `asyncio.to_thread` retains the loop default executor, copied context, concurrency bound and cancelled-wait behavior. |
| Async entry points | `asyncio.run` retains caller-thread loop and signal ownership and refusal inside an active loop. |
| Task-owned timeouts | `asyncio.wait_for` retains Task/Future ownership, zero/negative no-start behavior and Python3.10 TimeoutError identity. |
| Broadcaster coroutine replies | Broadcaster invokes subscribers in order, awaits coroutine results only, isolates ordinary errors and propagates cancellation; Future/Task results remain unawaited. |
| Worker cancellation and limiter controls | `run_sync` exposes existing bool abandon_on_cancel and CapacityLimiter controls, preserving backend-specific cancellation and limiter behavior. |
| Queue API boundaries | `ln.Queue` is a bounded stream-backed interface; native queue defaults, exceptions and introspection remain separate. |
| Lock and semaphore introspection | The shared lock/semaphore interfaces do not replace native `locked()` or fast-acquire consumers. |
| Main-thread loop ownership | Signal-sensitive loop entry points keep native main-thread ownership rather than adding a worker-thread run mode. |

## Shared helpers

`run_sync` offloads `_subagent_status`, `deliver_flow_notify_now`, `TerminalCallbackRegistry.emit` and Studio admin workers. Notifications and terminal callbacks explicitly select `abandon_on_cancel=True`; other callers keep the default shield. Admission retries and scheduler tick/restart delays use `sleep` without changing their surrounding deadline or cancellation handling.
